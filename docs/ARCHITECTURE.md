# Service Studio 架构审查与改造

## 审查结果

原来的 `backend/src/main.cpp` 同时承担进程启动、gRPC 鉴权、模型构建、协议回调、运行状态、波形和数据读写。直接在此类中继续加入以太网发布、TLS 和持久化，会扩大资源释放、锁顺序和失败恢复的影响范围。前端主进程则把工程文件、审计、菜单和全部命令放在同一文件；渲染进程把虚拟表格、导航树、属性弹窗和编辑界面混在一起。

本次将通信管理边界、协议扩展和文件操作分离。主服务只依赖自身的 IEC 61850 通信模块；抓包分析模块通过独立进程加载可选动态库，详见配套的报文分析研究与接口说明。

## 后端职责

| 模块 | 责任 | 不承担的责任 |
|---|---|---|
| `main.cpp` | 本机管理端口、父进程生命周期、CFG 校验入口 | 模型构建、控制业务 |
| `grpc_service.h` | 管理令牌验证、RPC 转发、异常到状态码转换 | IEC 模型资源所有权 |
| `server_engine.*` | IED 生命周期、运行状态和波形调度 | 证书解析、持久化文件格式 |
| `engine_operations.cpp` | Apply/Start/Stop/Update 等应用操作 | gRPC ServerContext |
| `model_builder.cpp` | 动态模型、数据集、报告构建与导入接线 | 网络发布循环 |
| `model_browser.cpp` | 模型遍历、对象引用与属性元数据 | 界面状态 |
| `control_handlers.cpp` | 遥控校验/执行/选择、连接与 RCB 事件 | 文件存储 |
| `project_validation.cpp` | 结构和数值约束 | 监听端口 |
| `tls_context.*` | TLSConfiguration RAII、凭据读取、证书/私钥匹配 | 工程中的私钥内容保存 |
| `setting_store.*` | SG/SE 配对、组切换、BER 值存储、事务提交 | UI 表格与 IPC |
| `publisher_service.*` | 网卡选择、GOOSE 重传、SV 调度、驱动结果与漏期统计 | 主 UI 刷新 |
| `publisher_model.cpp` | 导入 GSE/SV 控制块的发布配置模板 | 自动启用网卡发布 |

管理服务持有应用层 `ServerEngine`，但后者不再继承 gRPC Service。TLS、定值和发布器分别拥有资源；退出时先停止发布线程和 MMS 服务，再释放回调目标、IED、模型与 TLS 配置。Apply 构造失败会清理半成品并保持未配置状态，不能继续启动一个部分有效的工程。

## 并发与错误处理

生命周期操作使用 `op` 互斥锁。IEC 缓存访问使用 libiec61850 数据模型锁；同时需要运行状态时，先取模型锁，再取 `data`。libiec61850 在初始化与回调中可能重入状态记录，`data` 保留递归互斥语义。

发布器有独立工作线程和统计锁。帧值从选中的数据集复制，网络编码和发送不占用模型锁。SV 使用 Windows 高精度等待定时器；调度超过期限时跳过过期周期并累加漏期计数，不无限补发形成报文突发。smpSynch 固定为 0，表示没有外部时钟同步。GOOSE 的值变化增加 stNum，重传增加 sqNum，周期从 MinTime 退避到 MaxTime。

定值编辑确认在持有模型锁的协议回调中完成：序列化候选银行、写临时文件、FlushFileBuffers、MoveFileExW 替换，成功后才更新内存银行及激活 SG。新增的事务确认回调可返回失败；写盘失败时 MMS 客户端收到错误，编辑预约保留，原银行继续有效。持久化保存 MMS BER 类型值，不通过浮点或展示字符串中转。

## 前端职责

主进程保留应用编排和工程操作。`storage.js` 负责原子文件写入、定值银行路径及审计轮转；`native-menu.js` 构建原生菜单；`protocol-commands.js` 映射协议操作；`ipc-guard.js` 统一验证窗口、主 frame 和 URL；`replay-target.js` 提供受限测量值回放目标。导入器、后端进程客户端和 preload 各自保持独立。

渲染进程采用 ES 模块。属性弹窗、导航树、虚拟表格、点位/数据集/报告编辑器、表单组件及 TLS/发布/定值对话框位于 `views/`，通过显式参数和状态读取函数连接主控制器。属性弹窗自行持有请求序号，关闭或新请求后丢弃旧结果。

表格与导航树均使用固定行高的可见区渲染；滚动合并到 requestAnimationFrame。点值刷新只改动可见单元格，选择不重建表格。测试不向产品注入全局调试入口，而是导入明确导出的控制器方法准备大模型夹具。

## 构建可靠性

MSVC 中文 `showIncludes` 输出曾被 CMake/Ninja 以错误编码识别，导致头文件变更没有正确触发重编译。构建脚本现在在调用 VS 环境前切换 UTF-8 代码页，并设置 VSLANG；使用重新配置的 `backend/build-v2` 缓存。全量重建后，头文件变更触发对应编译单元重编译，避免类布局新旧混用。

第三方局部修改保存在源码中并列于 `THIRD_PARTY.md`：Unicode 文件接口、定值事务回调、TLS 对端名称/证书密钥校验和 Windows 以太网驱动发送结果。修改不通过覆盖整份上游代码实现。

## 验证范围

`test:integration` 验证真实 MMS 读值、动态数据集、URCB/BRCB、控制模型和导入；`test:security` 验证双向 TLS、拒绝未受信和明文连接、TLS 1.3、SG/SE 客户端预约、确认、切换、进程重启及写盘失败；`test:publishers` 在隔离 VMnet1 抓取真实以太网帧，验证 GOOSE 和 SV 的计数与值；`test:ui` 验证桌面菜单、属性弹窗、协议配置和 1 万对象下的有界 DOM。

抓包分析的验收单独管理，组件不可用不得使上述主应用用例失败。协议测试不能替代 IEC 一致性认证、长时间运行和现场网络验收。

以太网驱动采用延迟加载，MMS 启动不依赖 Npcap；只有打开网卡列表或启用发布时才从系统驱动目录解析 wpcap.dll。

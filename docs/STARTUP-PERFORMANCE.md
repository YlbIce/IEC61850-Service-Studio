# 便携版启动优化

## 根因与处理

本项目安装的 electron-builder NSIS portable 模板在每次启动时 `RMDir /r $INSTDIR`，解压所有应用资源后 `ExecWait`，退出时再次删除目录。仅设置固定解压目录不能消除这个模板的重复解压。主服务不在启动时加载抓包组件，但自解压包装器仍提前处理其所有文件。

Windows 便携发行目标改为 ZIP，安装包仍为 NSIS。ZIP 完整解压一次后直接启动主 EXE，保留后端、抓包组件和许可证，无需安装。应用配置位置沿用现有行为；本次没有迁移用户数据，也没有实现有缓存更新/清理风险的自定义启动器。

## 实测

Windows x64；Node 24.15；同一 0.2.1 发行目录与自解压 EXE。`node scripts/measure-startup.js --legacy` 使用独立测试配置，不启动 MMS 监听服务。从启动进程到主页面 preload 可用且原生后端配置就绪：

| 形式 | 耗时 |
|---|---:|
| 每次自解压的 Portable.exe | 32.369 秒 |
| 解压后的目录主程序 | 1.434 秒 |

单次顺序对照，受文件缓存、存储与安全软件影响，不代表严格冷启动统计。耗时缩短约 95.6%。原始结果见根目录 `startup-results.json`。后续启动无需重复解压；首次下载 ZIP 的解压耗时不计入目录启动数值。

发行验收需完整解压 ZIP、运行实际主 EXE，验证后端配置、MMS 启停及可选抓包组件加载。


默认基准只运行目录版本。`--legacy` 会先拒绝任何仍有 Service Studio 进程的环境：旧包装器的临时目录在构建时确定，不同 userData 参数不能隔离解压目录。0.2.2 ZIP 不使用这个共享临时目录。

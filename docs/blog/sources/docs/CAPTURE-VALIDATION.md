# 报文模块验证记录与交付边界

本记录逐项对应 [CAPTURE-REQUIREMENTS.md](CAPTURE-REQUIREMENTS.md)，区分已经执行的测试和设计目标。核查日期为 2026-09-10；TShark 版本为 4.6.8，Windows x64，Npcap loopback。未执行的测试不会因使用了 Wireshark 解码器而被视为通过。

## 验证入口与真实证据

- 原生编译与真实链路回归：`node scripts/build-capture.js --test-client`，然后 `node scripts/test-capture-backend.js`。捕获真实 libiec61850 客户端与本机 MMS 服务通信，包含 71 个 MMS 帧；本次样本为 `backend/capture/test-output/中文 MMS 1789025160839.pcapng`。
- 上述固定样本的 SHA-256 为 `06C878DF5B59AF946E3A3A6232EAEE6A2081C0EA824F02392E407E0BECFC20DB`。重新运行实时测试会生成新的文件及时间戳，应重新计算哈希，不能直接沿用此值。
- MMS 语义适配器以 MSVC C++17 编译测试，使用上述 TShark 层级 JSON，而非列摘要文本。验证单点 Read 值 220、确切引用及 FC，URCB/BRCB 稀疏报告、结构值、质量原位串、UTC 纳秒、Write 意图排除、访问错误/截断排除，以及 UINT64_MAX 精度。
- 目录映射验证：真实 frame 138 的 GetNamedVariableListAttributes 请求与 frame 140 响应生成 `STUDIOLD0/LLN0$Measurements` 的四个确切成员。目录出现前的报告仍未解析，目录出现后的报告才可映射回放。
- 前端数据层：`node backend/capture/tests/frontend-performance.js`。直接导入生产 `src/capture/packet-repository.mjs`，10 万逻辑帧、500 页、最大保留 20 页/4000 行，50 个同页并发请求合并为 1 个；过期结果、重置竞态、失败重试及缩小过滤结果测试通过。10 万次可视范围计算本次为 8.7 ms，最大范围 48 行。这不是实际绘制帧率或原生解码速度的测量。
- 大文件及缓存：`node backend/capture/tests/performance.js`。离线生成以太网/IPv4/UDP 压力文件，另用真实 MMS 文件检查语义回放。首次试运行发现非 MMS 帧详情重复扫描；修复通用详情缓存后的完整 100 MB 测试已经通过。最终数值见下方及 `.tmp/capture-performance/result.json`，不引用已中止试运行作为通过依据。
- UI 的初步自动检查已经覆盖缺 helper 状态的独立窗口、沙盒及 `typeof require === 'undefined'`、中文 PCAPNG 和非标准端口、显示过滤、会话表、协议树和 hex、原生右键项、离线步进及显式映射接口。注入接口测试使用 mock 目标，不等同于真实目标白名单或仿真互斥验证。

## 压力测试最终结果

本次无错误运行状态为 `passed`，Node v24.15.0，Windows x64，TShark 4.6.8。以下全部为实际测量，不是设计预算：

| 项目 | 结果 | 解释 |
|---|---:|---|
| 压力文件 | 108,200,024 字节 / 100,000 帧 | 离线生成 Ethernet/IPv4/UDP；没有向网络发包 |
| 首次摘要索引 | 38.83 秒 | 冷分析需等待，不宣称首次打开秒开 |
| 60 次分页查询 p95 | 4.75 ms | 每页 200 行，覆盖整个索引 |
| 首次中部帧详情 | 15.39 秒 | 包含一次 MMS 语义索引与该非 MMS 帧冷解码 |
| 20 次同帧缓存详情 p95 | 3.62 ms | 修复前此路径反复全文件扫描；修复后回归通过 |
| helper 峰值工作集 | 8.12 MiB | 只统计 capture-helper，不包含 TShark 子进程；不能作为总进程内存 |
| 索引取消 | 26.9 ms | 返回 CANCELLED，不是错误被吞掉或任务先完成 |
| 真实 MMS 事件索引 | 7.77 秒 | 小型 71-MMS 帧真实样本，非 UDP 压力数据；得到 8 个可回放事件 |
| 100 次真实 MMS snapshot 定位 p95 | 1.93 ms | 来回定位，末尾快照一致，没有重复解码文件 |

生产前端数据层额外通过 50 次同页请求去重、重置时过期结果丢弃、失败重试、LRU 限额和滚动后筛选缩小的边界测试。最大可视范围为 48 行；没有把纯 JavaScript 范围计算的耗时包装成实际 Electron 画面刷新率。

测试脚本把结果保存到 `.tmp/capture-performance/result.json` 和 `.tmp/capture-performance/frontend-result.json`。前者记录真实 MMS 文件路径以及是否跳过该样本；本次未跳过。首次试运行发现并修复非 MMS 详情扫描瓶颈的历史保留，当前成功数值均来自修复后的完整运行。

1 GB 输入、长期实时抓取、TLS 密钥解密、独立 SCL 映射、分段报告组装、字段到字节同步以及满负载主服务时延，本记录均未写为通过。
